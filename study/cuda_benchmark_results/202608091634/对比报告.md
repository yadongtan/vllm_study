# 并行 CUDA Attention 与 PyTorch SDPA 对比

测试开始时间：2026-08-09 16:34（目录：`202608091634`）
GPU：NVIDIA GeForce RTX 4080 SUPER
模型：Qwen2-0.5B-Instruct
请求设置：1/4/8 并发；每轮 128 请求；1000 token 输入；50 token 输出；忽略 EOS；BF16。
两种后端共用同一份模型、调度器、KV Cache 和采样逻辑，区别仅为 Attention：

- `custom-cuda`：`torch.ops.study_cuda.ragged_gqa_attention`，保留 GQA 头布局，CUDA block 内线程并行完成 QK、softmax 和 PV。
- `torch-sdpa`：原始 PyTorch `scaled_dot_product_attention`，显式复制 GQA K/V 并构造请求边界 mask。

## 结论与边界

1. 线程并行 CUDA 版本已在 1000-token 长输入和 1/4/8 并发下稳定完成全部请求，结果与 SDPA 的 BF16 误差在预期范围内。
2. 自定义版本保留紧凑 GQA K/V，没有显式复制 7 份 K/V；并发 8 时显存利用率约 22%，Torch SDPA 约 59%，体现了本阶段的内存布局收益。
3. 当前 CUDA kernel 是教学用的直接公式实现，不是 FlashAttention；QK、softmax 和 PV 仍有进一步 tile、warp-level reduction、online softmax 和 paged KV cache 优化空间。
4. `202608091613` 是修复同步竞态前的失败轮次：自定义 CUDA 产生 device-side assert，三份 custom JSON 的 `completed=0`，不纳入本报告。
