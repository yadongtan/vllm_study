# CUDA Flash Attention V1 性能对比报告

## 1. 测试结论

`STUDY_USE_CUDA_FLASH_ATTENTION_V1=1` 已完成 1、4、8 并发测试，每档均为
128/128 请求成功、0 请求失败，服务日志中未发现 CUDA 异常。

当前 V1 实现没有获得性能提升。与上一版 `custom-cuda` 相比：

- 并发 1：请求吞吐下降 53.2%，平均 TPOT 增加 120.5%。
- 并发 4：请求吞吐下降 83.2%，平均 TPOT 增加 488.8%。
- 并发 8：请求吞吐下降 90.0%，平均 TPOT 增加 888.8%。

并发从 1 提升到 8 时，V1 的 GPU 平均利用率从 83.57% 上升到 95.04%，
但输出吞吐从 13.90 tok/s 下降到 8.19 tok/s。这说明瓶颈不是 GPU 未被使用，
而是 GPU 执行了大量串行和无效计算。

## 6. 为什么 GPU 利用率高但性能更低

当前 kernel 已使用在线 softmax，避免保存完整注意力矩阵；但是计算映射仍有以下
明显瓶颈：

1. 每个 CUDA 线程独自负责一个 query token，并串行完成该 token 的全部
   `head_dim` 点积、softmax 和 `V` 加权，没有让一个 warp 协作计算同一个 query。
2. 每个 query 都从 0 扫描到打包后全部 `kv_seq_len`。即使某个 KV 属于其他请求，
   也会先完成 QK 点积，再通过 mask 将 score 设为负无穷，因此并发越高，跨请求
   无效计算越多。
3. decode 时每个 query 必须读取自己的历史 KV，这是标准全注意力不可避免的；
   但当前实现额外读取并计算了其他并发请求的 KV，这部分可以消除。
4. QK 的 `head_dim` 循环和 PV 的 `head_dim` 循环都是单线程标量循环，尚未使用
   warp reduction、向量化 load、shared-memory tile 或 Tensor Core。
5. 因此并发升高后，GPU 长时间忙于更多工作，利用率接近 100%，但每单位时间
   完成的有效 token 反而减少。

所以当前 V1 可以看作“使用在线 softmax 的第一版教学实现”，还不能等同于
vLLM/FlashAttention 中经过分块、warp 协作、向量化和请求边界优化的高性能实现。
