# CUDA Flash Attention V2 性能对比报告

## 1. 测试结论

设置 `STUDY_USE_CUDA_FLASH_ATTENTION_V2=1` 后，1、4、8 并发均完成
128/128 请求，失败请求为 0，服务日志中没有 CUDA 异常。

V2 的 Q/K tile 并行和第二阶段归约相比 V1 获得了明显提升：

- 并发 1：输出吞吐提升 244.7%，平均 TPOT 降低 72.3%。
- 并发 4：输出吞吐提升 382.9%，平均 TPOT 降低 81.4%。
- 并发 8：输出吞吐提升 352.5%，平均 TPOT 降低 79.6%。

但是 V2 的并发扩展仍然不理想：输出吞吐在并发 1/4/8 下分别为
47.91、53.43、37.04 tok/s，并发 8 反而比并发 4 低 30.7%。相对旧
`custom-cuda`，V2 在并发 1 快 61.3%，但在并发 4 和 8 分别慢 18.7%
和 54.7%。

主要问题是 V2 为每个 KV tile 保存 FP32 的 `partial_max`、`partial_sum` 和
`partial_o`，其中 `partial_o` 的大小随
`num_heads × q_seq_len × num_kv_blocks × head_dim` 增长。并发 8 测试期间
平均显存达到 8527.7 MiB，峰值达到 8819 MiB。

## 6. V2 的优化收益和剩余问题

### 已获得的收益

1. Q/K 使用 32×32 tile，不再由一个线程串行扫描完整 KV。
2. 128 个线程并行计算 tile 内 score。
3. 一个 warp 协作执行每个 query row 的 max/sum reduction。
4. KV tile 的 partial softmax 结果由第二个 kernel 数值稳定地合并。
5. GQA 仍通过 `q_head / group_size` 直接映射 KV head，不显式复制 K/V。

### 剩余瓶颈

1. 每个 `(Q tile, KV tile, Q head)` 都会启动 block；其他请求对应的 KV tile
   最终被 mask，但其 QK 点积已经执行，跨请求无效计算仍然存在。
2. `partial_o` 使用 FP32 并完整保存每个 KV block 的 `head_dim` 输出，空间复杂度
   随并发和序列长度迅速增长。
3. reduction kernel 需要再次读取全部 `partial_o`，增加大规模全局显存读写。
4. QK 内部 `head_dim=64` 的点积仍是每个 score 线程的标量循环，没有让 warp
   沿 D 维协作，也没有向量化 load 或 Tensor Core。
5. 并发 8 时平均 GPU 利用率达到 79.35%，但吞吐比并发 4 低 30.7%，说明增加
   的 GPU 工作主要不是有效 token 吞吐。

下一步最直接的方向是：按请求边界只生成有效 `(Q tile, KV tile)` 工作列表，消除
跨请求 tile；随后把跨 KV tile 的 online softmax 合并尽量放在一个 cooperative
kernel 内，减少或取消巨大的 `partial_o`。

## 7. 冷启动轮次说明

冷启动，但不纳入本报告的横向性能结论。

性能报告的正式数据。
