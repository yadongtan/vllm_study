# Vectorized Prefill KV Cache Write 性能测试报告

## 1. 结论

本轮只优化等长 batch 的 Prefill KV Cache 写入。原实现每层遍历每个请求，并通过
`.item()` 把 `prompt_len` 和 `cache_slot` 从 GPU 取回 CPU。batch 8、24 层时，
一次 Prefill 会产生 384 次 GPU 到 CPU 同步和 384 次独立 `index_copy_`。

新实现一次生成整个 `[batch, sequence]` slot mapping，把 K/V 整理为 packed
`[batch * sequence, kv_heads, head_dim]`，每层只执行两次批量 `index_copy_`。
变长 prompt 保留原循环路径。

相对 Causal Prefill Fast Path，1、4、8 并发输出吞吐分别提升 3.32%、7.36% 和
7.04%。三档均有收益，因此默认开启。

| 并发 | 上一版本 (tok/s) | 本轮 (tok/s) | 提升 | 原生 vLLM (tok/s) | vLLM / 本轮 |
|---:|---:|---:|---:|---:|---:|
| 1 | 257.69 | 266.25 | +3.32% | 375.19 | 1.41x |
| 4 | 477.20 | 512.33 | +7.36% | 1305.21 | 2.55x |
| 8 | 688.15 | 736.61 | +7.04% | 2400.77 | 3.26x |

## 2. 单一优化内容

默认环境变量：

```text
STUDY_USE_VECTORIZED_PREFILL_CACHE_WRITE=1
```

Profiler 中三轮 batch 8、1000-token Prefill 的变化：

| 指标 | 原请求循环 | 向量化写入 |
|---|---:|---:|
| `_local_scalar_dense` 调用 | 1155 | 3 |
| `index_copy_` 调用 | 1152 | 144 |
| Profiler CPU 总时间 | 395.89 ms | 276.22 ms |

剩余 3 次 `.item()` 来自每次 Prefill 对“是否全部等长”的一次检查，不再按层或按
请求重复同步。

## 3. 正确性验证

- 同一完整 24 层模型分别使用请求循环与向量化写入。
- 最终 logits 完全一致。
- 完整 K Cache 完全一致。
- 完整 V Cache 完全一致。
- Python 语法检查通过。
- 1、4、8 并发均成功完成 128/128 请求，失败为 0。

## 4. 测试口径

- GPU：NVIDIA GeForce RTX 4080 SUPER，16376 MiB。
- 模型：`/opt/models/Qwen2-0.5B-Instruct`，BF16。
- `max_model_len=2048`，`max_num_seqs=32`。
- CUDA Graph batch sizes：1、2、4、8、16、32。
- 并发 1、4、8；每档 128 请求。
- 每请求 1000 token 输入、请求生成 50 token。
- 无限请求速率、忽略 EOS、温度 0。
- 上一版本：`cuda_benchmark_results/202608142059`。
- 本轮：`cuda_benchmark_results/202608142105`。
- 原生 vLLM：`cuda_benchmark_results/202608140242`。

## 7. 下一步定位

同步问题消除后，Prefill GPU profile 的第一大可独立逐元素热点是 MLP 的
`SiLU(gate) * up`，三轮占约 17.5% CUDA 时间。下一轮应仅在 Prefill 启用已有的
Fused SiLU + Multiply，并保持 Decode 继续关闭，避免此前 Decode 小张量上的负收益。
