# Fused Prefill SiLU + Multiply 性能测试报告

## 1. 结论

本轮只在 Prefill MLP 中启用已有的 Fused SiLU + Multiply，自定义 kernel 直接从
`gate_up_proj` 的拼接输出读取 gate/up，计算 `silu(gate) * up`，避免 PyTorch 的
独立 SiLU kernel、中间结果和后续 Multiply kernel。

GPU profile 的三轮 batch 8 Prefill 总时间从 276.95 ms 降至 259.27 ms，下降
6.38%。但是端到端测试存在明显 batch 尺寸分界：并发 1/4 分别下降 0.83% 和
0.35%，并发 8 提升 4.99%。因此“所有 batch 强制融合”不作为最终默认策略，后续
使用 batch 门限自适应选择。

| 并发 | 上一版本 (tok/s) | 强制融合 (tok/s) | 变化 | 原生 vLLM (tok/s) |
|---:|---:|---:|---:|---:|
| 1 | 266.25 | 264.03 | -0.83% | 375.19 |
| 4 | 512.33 | 510.55 | -0.35% | 1305.21 |
| 8 | 736.61 | 773.39 | +4.99% | 2400.77 |

## 2. 单一优化内容

本轮测试强制设置：

```text
STUDY_USE_FUSED_PREFILL_SILU_MUL=1
STUDY_USE_FUSED_SILU_MUL=0
```

第二项继续保证 Decode 不使用该融合算子。本轮没有修改 Attention、KV Cache、
CUDA Graph、调度器或 LM head。

## 3. 正确性验证

- `[8, 1000, 9728]` BF16 大张量与 `F.silu(gate) * up` 对照通过。
- 完整 24 层 Prefill logits 在 BF16 容差内一致。
- 首个 next token 完全一致。
- K/V Cache 在 BF16 容差内一致。
- 1、4、8 并发均成功完成 128/128 请求，失败为 0。

## 4. 测试口径

- GPU：NVIDIA GeForce RTX 4080 SUPER，16376 MiB。
- 模型：`/opt/models/Qwen2-0.5B-Instruct`，BF16。
- `max_model_len=2048`，`max_num_seqs=32`。
- 并发 1、4、8；每档 128 请求。
- 每请求 1000 token 输入、请求生成 50 token。
- 无限请求速率、忽略 EOS、温度 0。
- 上一版本：`cuda_benchmark_results/202608142105`。
- 本轮：`cuda_benchmark_results/202608142111`。

## 7. 后续决策

下一轮只增加 batch-size 门限：小于 8 的 Prefill 使用 PyTorch SiLU + Multiply，
batch 8 及以上使用融合 kernel。这样保留大张量收益，同时避免小 batch 退化。
