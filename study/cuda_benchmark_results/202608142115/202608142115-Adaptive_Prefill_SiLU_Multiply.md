# Adaptive Prefill SiLU + Multiply 性能测试报告

## 1. 结论

本轮只增加 Prefill SiLU + Multiply 的 batch 门限：batch 小于 8 时使用 PyTorch
实现，batch 大于等于 8 时使用自定义融合 kernel。测试结果为 262.39 / 498.83 /
717.67 tok/s。

这轮结果没有超过上一轮最佳值。相对未融合版本，并发 1/4/8 分别变化 -1.45%、
-2.63% 和 -2.57%；相对强制融合版本分别变化 -0.62%、-2.30% 和 -7.20%。
因此门限逻辑保留为可配置实验能力，但这组端到端结果不支持把它认定为新的最佳
版本。后续优化仍以 `202608142105` 的小并发结果和 `202608142111` 的并发 8
结果作为对应参考。

| 并发 | 未融合版本 (tok/s) | 强制融合 (tok/s) | 自适应门限 (tok/s) | 相对未融合 | 相对强制融合 |
|---:|---:|---:|---:|---:|---:|
| 1 | 266.25 | 264.03 | 262.39 | -1.45% | -0.62% |
| 4 | 512.33 | 510.55 | 498.83 | -2.63% | -2.30% |
| 8 | 736.61 | 773.39 | 717.67 | -2.57% | -7.20% |

## 2. 单一优化内容

本轮仅测试以下选择逻辑：

```text
STUDY_USE_FUSED_PREFILL_SILU_MUL=1
STUDY_FUSED_PREFILL_SILU_MIN_BATCH_SIZE=8
STUDY_USE_FUSED_SILU_MUL=0
```

最后一项保证 Decode 不启用 SiLU 融合。本轮没有修改 Attention、KV Cache、
CUDA Graph、RMSNorm、RoPE、调度器或 LM head。

## 3. 正确性

- 门限两侧复用上一轮已通过的 PyTorch 和融合算子数值对照。
- 1、4、8 并发均成功完成 128/128 请求，失败请求为 0。
- 每个请求仍为 1000 token 输入、50 token 输出，模型输出流程正常。

## 4. 测试口径

- GPU：NVIDIA GeForce RTX 4080 SUPER，16376 MiB。
- 模型：`/opt/models/Qwen2-0.5B-Instruct`，BF16。
- `max_model_len=2048`，`max_num_seqs=32`。
- 并发 1、4、8；每档 128 请求。
- 每请求 1000 token 输入、请求生成 50 token。
- 无限请求速率、忽略 EOS、温度 0。
- 未融合版本：`cuda_benchmark_results/202608142105`。
- 强制融合版本：`cuda_benchmark_results/202608142111`。
- 本轮：`cuda_benchmark_results/202608142115`。
