# GQA Tile 16 性能测试报告

## 1. 结论

本轮只把 GQA Split-KV partial kernel 的协作加载 tile 从 8 个 KV token 增加到
16 个。正确性全部通过，但 Decode profile 和三档端到端吞吐均回退，因此该方案已
恢复为 8-token tile，不进入后续累计版本。

| 并发 | Warp RMS 基线 (tok/s) | GQA Tile 16 (tok/s) | 变化 | 原生 vLLM (tok/s) |
|---:|---:|---:|---:|---:|
| 1 | 269.43 | 260.61 | -3.27% | 375.19 |
| 4 | 518.61 | 491.64 | -5.20% | 1305.21 |
| 8 | 776.63 | 754.14 | -2.90% | 2400.77 |

## 2. 单一优化内容

每个 `(request, kv_head, partition)` block 会把 K/V token tile 协作加载到 shared
memory，再由同一 GQA group 的 7 个 query-head warp 复用。

本轮只把 `kGqaTileTokens` 从 8 改为 16。理论目标是在 64-token partition 内把
load/compute 两侧的 `__syncthreads()` 轮数从 8 轮降到 4 轮。partition size、grid、
block、workspace 和 CUDA Graph shape 均未修改。

## 3. 正确性验证

- Tile 16 与逐 query-head Split-KV 参考实现对照通过。
- CUDA Graph capture/replay 对照通过。
- 不同 partition 边界与 SDPA 参考实现对照通过。
- 1、4、8 并发均完成 128/128 请求，失败请求为 0。

## 4. Profile 变化

| batch 8，历史长度 1000，20 次 Decode | Tile 8 | Tile 16 | 变化 |
|---|---:|---:|---:|
| GQA partial kernel | 18.933 ms | 19.736 ms | +4.24% |
| Split-KV merge kernel | 1.907 ms | 1.906 ms | -0.05% |
| Self CUDA 总时间 | 62.894 ms | 64.151 ms | +2.00% |

更大的 tile 虽然减少同步次数，但每轮 block 必须等待更多协作加载完成，并使用更多
shared memory。对当前 64-dim head 和 7:1 GQA，8-token tile 的负载平衡更好。

## 5. 测试口径

- GPU：NVIDIA GeForce RTX 4080 SUPER，16376 MiB。
- 模型：`/opt/models/Qwen2-0.5B-Instruct`，BF16。
- `max_model_len=2048`，`max_num_seqs=32`。
- 并发 1、4、8；每档 128 请求。
- 每请求 1000 token 输入、请求生成 50 token。
- 无限请求速率、忽略 EOS、温度 0。
- 基线：`cuda_benchmark_results/202608142151`。
- 本轮：`cuda_benchmark_results/202608142201`。
