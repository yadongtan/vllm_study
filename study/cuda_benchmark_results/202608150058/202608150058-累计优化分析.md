## 3. 最终保留的新增优化

### Warp RMS reduction

用 warp shuffle 代替 256-thread shared-memory 八轮规约，把 Fused Add + RMSNorm
profile 降低 1.84%。

### Ignore-EOS D2H/Graph 流水

将当前 token 的异步 D2H copy 排在下一张 graph replay 前，用 event 只等待 copy，
CPU 处理当前 token 时 GPU 已执行下一步。移除了每 token 的
`positions.max().item()` 同步。

### 4-step batched notification

四组 pinned ring buffer 连续 enqueue graph，每个请求四个 token 只进行一次 Condition
通知和 tokenizer decode。提高吞吐，但平均 ITL 从约 3 ms 增到约 10-11 ms。
`STUDY_PIPELINE_STEPS=1` 可恢复平滑逐 token 模式。

### Parallel Split-KV merge

32 个 lanes 并行规约 partition max/sum，并缓存 exponential correction，避免每个输出
维度重复计算 exponential。Merge kernel 降低 28.37%。

## 4. 已实测否定的简单方向

- SiLU 二维 tile 与每线程 4 元素：整数索引减少，但显存带宽成本不变。
- GQA shared tile 16：同步次数减少，但协作等待与 shared-memory 压力增加。
- Partition 32/128：分别增加 merge/空 partition 成本，或降低 partial 并行度。
- Q layout copy 改 einsum：隔离微基准无收益，且 BF16 规约顺序产生更大差异。
- BF16 packed K/V load：原标量访问已经合并，宽化没有降低实际瓶颈。
- 强制 unroll 8-token loop：增加代码体积与寄存器活跃范围。
- Warp 广播 page lookup：同址读取已命中缓存，shuffle 更贵。
- 固定 batch wait 2 ms：高并发请求被拆成较小 graph batch。

## 5. 与 vLLM 的剩余差距

当前并发 8 仍比原生 vLLM 低 58.49%。最新 Decode profile 中，主要 CUDA 时间为：

- cuBLAS/CUTLASS projection GEMM：约 58%；
- GQA Split-KV partial attention：约 31%；
- Fused RMSNorm、RoPE 和其他 elementwise：其余约 11%。

剩余差距不能再通过简单循环、load 宽化或常量调参可靠消除。下一阶段需要架构级工作：

1. 使用 CUTLASS/CuTe 为 decode M=1/4/8 GEMM 做专用 persistent/fused kernel；
2. 将 QKV projection、RoPE、KV write 或 gate/up activation 更深地融合到 GEMM epilogue；
3. 重写 GQA partial 为多 warp/token 并行或接入 FlashInfer/vLLM paged attention；
4. 实现真正 continuous batching，让 Prefill、Decode 和新请求动态共存；
5. 使用异步 output processor 和成熟增量 detokenizer，避免以 4-token chunk 换吞吐；
6. 为 variable-length graph 构建 piecewise capture 和调度元数据更新。

这些方向会同时改变多个 kernel、内存布局或调度契约，不能满足“每次只改一个小方向”
的低风险前提，应作为下一阶段分别设计、验证和测试，而不是继续在当前 kernel 上做
无依据微调。
