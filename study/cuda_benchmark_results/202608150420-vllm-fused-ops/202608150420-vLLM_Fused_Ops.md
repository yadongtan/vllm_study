# 202608150420 - vLLM Fused RMSNorm 与 SwiGLU 算子

## 1. 本轮优化

项目此前已经实现 Fused Add + RMSNorm 和 SiLU + Multiply，但它们是用于学习的通用
自定义 CUDA kernel。vLLM 对同类算子使用经过向量化、warp 归约和不同 shape 调优的
`torch.ops._C` CUDA 实现。

本轮增加 `STUDY_USE_VLLM_FUSED_OPS=1`，只替换以下逐层高频操作：

- 首次 RMSNorm：`torch.ops._C.rms_norm`。
- 残差相加 + RMSNorm：`torch.ops._C.fused_add_rms_norm`，原地更新 input 和 residual。
- SwiGLU 激活：`torch.ops._C.silu_and_mul`。

QKV/Gate-Up/Down/Output GEMM、FlashAttention、Paged KV Cache、调度器和 CUDA Graph
batch sizes 均保持不变。本轮基准未启用 mixed Prefill/Decode，确保性能变化只来自 fused
算子替换。

## 2. 正确性验证

新增 `test_vllm_fused_ops.py`，在 CUDA BF16 上逐项对比项目原有实现：

- batch 8、hidden size 896 的 RMSNorm。
- batch 8、hidden size 896 的 Fused Add + RMSNorm，同时检查 output 和 residual。
- batch 8、Gate-Up size 9728 的 SiLU + Multiply。

三项均通过 `atol=2e-2, rtol=2e-2` 的 BF16 容差。完整服务的 1/4/8 并发各完成
128 请求，失败数均为 0；这也验证了 vLLM fused ops 可以被当前固定 batch CUDA Graph
正常 capture 和 replay。

## 3. 性能结果

测试口径：1000 input tokens、50 output tokens、128 requests、并发 1/4/8、
`max_model_len=2048`。基线为 `202608150310-vllm-flash-attn`，两边都启用异步输出复制和
vLLM FlashAttention Paged KV。

| 并发 | 基线输出吞吐 | vLLM fused ops | 变化 | 基线平均 ITL | 新平均 ITL | 基线/新 TTFT |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 363.65 tok/s | 381.00 tok/s | +4.77% | 2.20 ms | 2.16 ms | 25.41 / 20.94 ms |
| 4 | 982.74 tok/s | 1115.46 tok/s | +13.51% | 2.93 ms | 2.69 ms | 53.95 / 41.79 ms |
| 8 | 1471.26 tok/s | 1685.51 tok/s | +14.56% | 3.84 ms | 3.24 ms | 75.24 / 71.19 ms |

三个并发档位的吞吐、ITL 和 TTFT 总体一致改善，尤其并发 4/8 的收益超过 13%，说明
原先自定义 fused kernel 的向量化、归约和访存效率仍是重要瓶颈。该优化有效，建议作为
后续累计版本的默认路径。

## 5. 结论与后续

复用 vLLM 成熟 fused ops 是继 FlashAttention 后又一项显著提升。当前 8 并发输出吞吐
达到 1685.51 tok/s，相对原生 vLLM 历史对照 2400.77 tok/s，差距缩小到约 1.42 倍。

剩余可验证方向：

1. 将本轮 fused ops 与上一轮 mixed Prefill/Decode 累计启用，确认收益是否叠加。
2. 完整 chunked prefill 状态机，用剩余 token budget 处理 prompt chunk。
3. GPU-side finished/EOS 状态，扩大异步输出路径适用范围；该项不会改善当前
   `ignore_eos=true` 基准，但会改善真实普通请求。
