# 202608150618 - 独立 Engine 进程

## 1. 本轮优化

本轮参考 vLLM 的 API/engine core 隔离方式，新增 `STUDY_USE_ENGINE_PROCESS=1`：

- 主进程负责 tokenizer、HTTP、SSE 和增量 detokenization；
- 子进程独占 CUDA 模型、KV Cache、CUDA Graph 和 scheduler；
- 输入 prompt 通过进程队列交给 engine；
- 每个 GPU step 把整批 token 作为一条 IPC 消息返回；
- 没有等待凑批，也没有合并多个模型 Decode step。

## 2. 性能结果

| 并发 | 同进程基线 | 独立 Engine | 变化 |
|---:|---:|---:|---:|
| 16 | 2155.08 | 1923.04 | -10.8% |
| 32 | 2536.63 | 2466.35 | -2.8% |

表中为按实际生成 6400 token 校正后的 output tok/s。

| 并发 | 时长 (s) | 客户端 tok/s | 校正 tok/s | TTFT (ms) | TPOT (ms) |
|---:|---:|---:|---:|---:|---:|
| 16 | 3.328 | 1899.60 | 1923.04 | 142.75 | 6.69 |
| 32 | 2.595 | 2436.68 | 2466.35 | 192.46 | 11.16 |

## 3. 资源结果

| 并发 | GPU 平均/峰值 | 显存平均/峰值 | CPU 平均/峰值 | 内存平均/峰值 |
|---:|---:|---:|---:|---:|
| 16 | 24.6% / 97% | 3986 / 4037 MiB | 4.47% / 9.14% | 3459 / 3795 MiB |
| 32 | 22.4% / 95% | 4037 / 4038 MiB | 4.94% / 9.21% | 3611 / 3841 MiB |

加载完成、测试前 GPU/CPU 平均利用率为 4.4% / 0.07%。独立解释器和 IPC 队列使
主机内存明显增加，但没有增加 GPU 常驻显存。

## 4. 结论

进程隔离让 32 并发 TPOT 从 11.46 ms 小幅降到 11.16 ms，说明移除 API GIL 竞争确有
局部作用；但 Python `multiprocessing` 对 prompt list 和每步 token batch 的 pickle/队列
传输增加了 TTFT 与端到端开销，最终吞吐下降。

因此该路径保留为默认关闭的架构实验。vLLM 使用共享内存、专用消息协议和持久化 engine
core，不能只靠通用 Python Queue 获得同等收益。逐 token 时间线进一步显示当前一波请求
的主要时间仍由 Prefill 加 Decode 占用，下一轮优先测试高并发下的 vLLM FlashAttention
Prefill，而不是继续堆叠 IPC 复杂度。
