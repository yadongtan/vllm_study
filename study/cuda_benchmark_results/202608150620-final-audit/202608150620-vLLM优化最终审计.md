## 5. vLLM 优化覆盖审计

已经实现并验证：

- Continuous batching 与每步 token budget。
- 固定地址 Paged KV Cache、请求结束释放 cache slot。
- Split-KV、GQA KV tile 复用和有效 tile 工作列表。
- CUDA Graph batch sizes 1/2/4/8/16/32。
- Fused Add + RMSNorm、Fused RoPE + KV write、Fused SwiGLU。
- vLLM FlashAttention Paged-KV Decode。
- vLLM FlashAttention 等长 Prefill（可选，改善 TTFT）。
- 异步 token D2H copy。
- Packed mixed Prefill/Decode 学习实现和跨层 RoPE metadata 复用。
- vLLM 原生 fused RMSNorm/SwiGLU operators。

已经测试但不作为默认：

- Python eager mixed Prefill/Decode：未使用等待凑批，但 metadata/Tensor 构造抵消收益。
- FlashAttention Prefill：并发 8 TTFT 改善约 18%，输出吞吐轻微下降约 1%。
- 自写 SiLU kernel：不如 vLLM 向量化实现稳定。
- Whole-model `torch.compile` + 外层 CUDA Graph：出现嵌套 Graph capture 或逐层重编译，
  当前结构下不保留。

不适用于当前同口径测试：

- Prefix caching：随机 prompt 没有公共前缀。
- Speculative decoding：改变每步工作量。
- INT8/FP8/量化：改变精度口径。
- 等待凑批、quiet window、minimum batch：属于用户明确禁止的测试技巧。

## 6. 尚未完整移植的架构能力

剩余主要是一个整体，而非可再独立替换的小算子：vLLM 的持久化 GPU Model Runner、
预分配 input/metadata buffer、完整 chunked-prefill 状态机和异步调度状态。这些组件共同让
并发 4/8 时 batch 更稳定，并避免 Python 每轮创建 packed Tensor。当前 mixed 实验已经证明，
只复制“公式”而没有复制持久 runner，会因 metadata 开销变慢。

GPU-side EOS/finished mask 也尚未覆盖普通请求；它能扩大异步输出适用范围，但不会改善本次
`ignore_eos=true` 基准。继续实现需要一次独立的 scheduler/GPU runner 重构，已经超出
“逐项可验证单点优化”的阶段。
