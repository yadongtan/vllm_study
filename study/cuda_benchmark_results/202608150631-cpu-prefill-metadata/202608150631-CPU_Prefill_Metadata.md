# 202608150631 - CPU Prefill Metadata

## 1. 本轮优化

尝试将 prompt 最大长度和等长判断保留在 CPU，避免 `pad_prompts` 与模型 Prefill 中的
GPU scalar `.item()`。目标是减少每个最多 2048 token Prefill 小批次前的 host/device
同步，设计上对应 vLLM scheduler 使用 CPU metadata 驱动 model runner。

## 2. 性能结果

表中为按实际生成 6400 token 校正后的 output tok/s。

## 4. 结论

移除 scalar 同步没有改善端到端吞吐。该 `.item()` 主要等待同一 CUDA stream 中已经
排队的前序 Prefill 工作，GPU 本身仍持续执行；当前实现也没有第二条可并发提交的模型
stream，因此只移动同步位置不足以获得收益。该改动已回退，不进入默认路径。

下一轮改为在服务启动阶段执行一次最大 token budget 的 Prefill 预热，使首次正式请求
不再承担 kernel 加载与 GEMM 算法初始化成本。这是 vLLM model runner 的常规启动流程，
不会改变正式请求的调度或生成语义。
