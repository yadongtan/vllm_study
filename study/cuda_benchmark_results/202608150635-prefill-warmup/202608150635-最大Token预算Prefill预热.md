# 202608150635 - 最大 Token 预算 Prefill 预热

## 1. 本轮优化

参考 vLLM model runner 的启动预热流程，服务在开始接收请求前执行一轮接近
`max_num_batched_tokens` 的假 Prefill，并丢弃全部输出。当前配置使用：

```text
batch=2, sequence_len=1024, total_tokens=2048
```

预热覆盖 embedding、24 层 Prefill、causal attention、KV Cache 写入、MLP、LM head 和
argmax，使 cuBLAS/Flash kernel 加载、算法选择与运行时 workspace 分配不再落到首批正式
请求上。它不等待凑批，也不改变正式请求的输入、调度或生成结果。

## 2. 同轮 A/B 结果

关闭预热的对照保存在相邻目录 `202608150636-prefill-no-warmup`。

| 并发 | 无预热 | 最大预算预热 | 变化 |
|---:|---:|---:|---:|
| 16 | 1835.41 | 1949.11 | +6.2% |
| 32 | 2402.19 | 2439.27 | +1.5% |

表中为按实际生成 6400 token 校正后的 output tok/s。

| 并发 | 无预热/预热 TTFT (ms) | 无预热/预热 TPOT (ms) |
|---:|---:|---:|
| 16 | 137.58 / 112.50 | 7.29 / 7.28 |
| 32 | 174.00 / 164.61 | 12.07 / 12.03 |

收益主要来自首波 Prefill 和 TTFT，稳态 Decode TPOT 基本不变，符合该优化的预期。

## 3. 资源结果

| 阶段/并发 | GPU 平均/峰值 | 显存平均/峰值 | CPU 平均/峰值 | 内存平均/峰值 |
|---:|---:|---:|---:|---:|
| 加载后 | 7.6% / 15% | 4260 / 4261 MiB | 0.05% / 0.12% | 2417 / 2419 MiB |
| 16 | 35.8% / 95% | 4266 / 4273 MiB | 4.52% / 9.64% | 2961 / 3185 MiB |
| 32 | 35.5% / 97% | 4272 / 4273 MiB | 4.58% / 9.09% | 2992 / 3205 MiB |

预热后 CUDA runtime 保留约 250 MiB 额外 workspace；这是一次性常驻分配，测试期间显存
保持稳定，没有随请求增长。

## 4. 决策

同轮 16/32 并发均有正收益，且行为与 vLLM 启动预热一致，因此
`STUDY_USE_PREFILL_WARMUP` 默认改为 1；仍可设为 0 用于对照或缩短开发启动时间。

下一轮去除完成请求的末尾多余 Decode replay。当前 ignore-EOS 快路径在发布最后一个 token
之前仍会先计算下一 token，所有请求同时结束时整张 CUDA Graph 的结果都会被丢弃。
