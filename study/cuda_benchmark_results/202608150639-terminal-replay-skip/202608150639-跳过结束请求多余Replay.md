# 202608150639 - 跳过结束请求多余 Replay

## 1. 本轮优化

ignore-EOS 异步快路径原先按以下顺序执行：

1. 复制当前待发布 token；
2. 立即 replay 下一次 CUDA Graph；
3. 检查当前 token 是否已经达到 `max_tokens`；
4. 若全部请求结束，丢弃第 2 步结果。

这会让每一波固定 50-token 请求额外计算第 51 个 token。本轮在 replay 前根据已知的输出
长度和上下文上限判断是否还有请求需要下一步；全部结束时不再启动 CUDA Graph。

## 4. 决策

该改动不是主要吞吐突破口，但它删除了确定无效且结果必然被丢弃的模型执行，行为也与
vLLM 不再调度已完成序列一致，因此保留。

下一轮实现交错 Prefill/Decode。当前非 mixed scheduler 会先把全部可用 slot 逐批 Prefill
完再开始 Decode；新路径在每次 admission 时先用现有 CUDA Graph 推进 active requests，
再执行新 prompt Prefill，保持 2048 token budget 不变。
