## 2. 自研 Qwen3.5 实现

主要代码：`study/inference_engine/qwen3_5_demo_v1.py`。

Qwen3.5 是混合架构，不是纯 Qwen2 全注意力：

- 8 个 full attention 层使用 paged KV cache、GQA 和 vLLM FlashAttention。
- 24 个 Gated DeltaNet linear attention 层使用 recurrent state cache。
- 线性注意力层另有 causal convolution state cache。
- 支持 packed prefill、mixed prefill/decode 和 CUDA Graph decode 接口。
- loader 将 QKVZ、BA、MLP gate/up 等 checkpoint 张量融合到运行时布局，并跳过视觉塔和 MTP 权重。

启动自测已通过：真实权重加载了 426 个文本张量；prefill 和 decode 输出形状均为 `(2, 248320)`，GPU 显存约 9.05 GiB。

## 4. 性能结果

| 实现 | 并发 | 成功/失败 | 用时 (s) | 请求/s | 输出 token/s | 6400/用时 token/s |
|---|---:|---:|---:|---:|---:|---:|
| 自研 Qwen3.5 | 16 | 128/0 | 19.54 | 6.55 | 327.53 | 327.53 |
| 原生 vLLM | 16 | 128/0 | 21.13 | 6.06 | 302.82 | 302.82 |
| 自研 Qwen3.5 | 32 | 128/0 | 17.75 | 7.21 | 360.55 | 360.55 |
| 原生 vLLM | 32 | 128/0 | 16.24 | 7.88 | 394.17 | 394.17 |

相对原生 vLLM：

- 16 并发：自研吞吐高约 8.2%，但单轮时间更短；两次测试的 GPU 初始状态、采样点数和启动缓存状态存在差异，不能据此判定自研内核整体优于 vLLM。
- 32 并发：自研为 vLLM 的 91.5%，低约 8.5%。高并发时 vLLM 的连续批处理和 GDN 专用 kernel 开始体现优势。

## 6. 差距分析

当前实现已经复用了 vLLM 的部分 FlashAttention、fused RMSNorm/SwiGLU 和 fused RoPE/cache 写入路径，但仍不是 vLLM 的完整 Qwen3.5 执行器：

1. Gated DeltaNet prefill 仍有 `index_select/index_copy` 状态搬运；vLLM 使用面向 packed batch 的专用 kernel，减少中间张量和 kernel launch。
2. GDN 的 RMSNorm、SiLU gate 和状态更新没有完全融合；多次读写 hidden/state 会降低高并发下的有效计算密度。
3. full attention 的 Q/K norm、partial RoPE、KV 写入仍包含多个独立 PyTorch 操作；vLLM 将这些步骤与调度、cache 写入及 attention backend 更紧密地组合。
4. 自研服务的 Python 调度、请求状态管理和输出复制路径仍有额外开销；vLLM 的 scheduler、block manager 和 CUDA Graph 路径经过长期优化。
5. 当前测试只覆盖 text-only Qwen3.5 推理，尚未实现视觉输入和 MTP；这不影响本次文本吞吐对比。

因此，32 并发下约 8.5% 的差距主要来自 GDN 路径和调度/融合程度，而不是模型权重或测试工作量不一致。

## 7. 延迟与原始 JSON 说明

客户端为自研 OpenAI 兼容服务重新 tokenize 返回文本时，记录的
`total_output_tokens` 为 10630（并发 16）和 9412（并发 32），与请求约定的
`128 * 50 = 6400` 不一致。因此自研 JSON 中的 `output_throughput`（544.01 和
530.23 token/s）以及 `total_token_throughput` 不能直接与 vLLM 的对应字段比较；
本报告的吞吐统一使用固定的 6400 个输出 token。
