# Qwen3.5-4B Qwen2 能力基线性能报告

测试时间：2026-08-16 00:35（WSL Ubuntu 24.04）  
GPU：NVIDIA GeForce RTX 4080，显存 16376 MiB  
模型：`/opt/vllm_study/models/Qwen/Qwen3.5-4B`

## 1. 测试目标

本轮不是测试此前的 Qwen3.5 优化执行器，而是验证一个严格沿用
`qwen2_demo.py` 能力边界的 Qwen3.5-4B 基线：只增加 Qwen3.5 模型结构
必需的 24 层 Gated DeltaNet 和 8 层 full attention，不带入后续性能特性。

基线保留：

- Qwen2 `Request`、`Scheduler` 和 Chunked Prefill；
- packed 变长请求和普通每请求缓存；
- QKV、Gate/Up 融合参数及逐分片 Safetensors loader；
- full attention 使用 PyTorch SDPA；
- Delta Rule 使用模型必需的现有核心算子。

基线不使用：

- CUDA Graph；
- vLLM FlashAttention；
- Paged KV Cache；
- fused RMSNorm、SiLU、RoPE/cache write；
- mixed prefill/decode、持久化 mixed buffers；
- async output copy 和 batch output processor。

Qwen3.5 的 causal convolution 使用逐请求 PyTorch depthwise `conv1d + SiLU`。
开发冒烟测试中，直接复用优化 causal-conv CUDA 路径会在第 9 层产生非有限值；
改为基线 PyTorch 公式后，真实 426 个文本权重全部加载，Prefill 和 Decode 均成功。

## 5. 32 和 64 并发

32 并发运行约 8 分钟后仅完成 6/128 个请求：

- 第一个请求 TTFT 为 409.96 秒；
- 观察完成率约 0.0125 req/s；
- GPU 持续接近 100%，显存接近 16 GiB；
- 已明显低于并发 16 的 0.13 req/s。

因此停止 32 并发长跑，并不生成不完整的吞吐 JSON。64 并发未启动，因为它只会
进一步增加相同的每请求 recurrent/conv 状态与 full-attention 临时张量，不能形成
有意义的完整对比。资源 CSV 保留了 32 并发中止前的 492 个采样点。

## 7. 性能差异原因

1. **DeltaNet 状态搬运**：基线每层、每轮都 `stack` 每个请求的 recurrent state，
   计算后再逐请求 `clone` 回缓存。16 并发时仅 recurrent state 就形成大量显存读写。
2. **普通 causal convolution**：24 个线性 Attention 层对每个请求分别启动
   depthwise `conv1d`，没有 packed 专用 kernel 和 fused state update。
3. **GQA 显式复制**：full attention 使用 `repeat_interleave` 把 4 个 KV heads
   复制成 16 个 Query heads，额外放大 K/V 临时内存 4 倍。
4. **跨请求 dense 布局**：拼接所有历史 KV 后构造二维 mask；虽然 mask 屏蔽了
   跨请求位置，但 SDPA 仍面对大 packed 张量和复制后的 K/V。
5. **KV Cache 反复拼接**：每个 decode token 都通过 `torch.cat` 重新生成逐层
   K/V，不能像 Paged KV Cache 那样原地写入固定 page。
6. **没有 CUDA Graph 和融合算子**：每个 token 会启动大量 RMSNorm、RoPE、
   激活、状态更新和采样 kernel；优化版能显著减少 launch 与中间显存读写。

## 8. 结论

本轮证明 Qwen3.5-4B 可以在 Qwen2 的基础执行框架中正确加载和运行，但该框架
只适合教学和低并发公式验证，不适合 Qwen3.5 的生产吞吐：

- 正确性：真实 426 个文本张量加载成功，1–16 并发全部请求成功；
- 最佳基线：并发 8，70.95 output token/s；
- 优化价值：同并发 8，优化版 253.99 token/s，是基线的 3.58 倍；
- 高并发边界：16 并发显存接近满载且吞吐崩塌，32/64 不可用；
- 此前 Qwen3.5 优化版达到 vLLM 约 92%–98%，说明主要差异确实来自执行器、
  cache、kernel 和调度优化，而不是模型本身。
